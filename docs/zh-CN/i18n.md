# 国际化

[English](../i18n.md)

Oh My DSH 当前提供 `en` 和 `zh-CN` 文案。

## 语言选择

命令行工具按以下优先级选择语言：

1. `--locale <tag>` 或 `--locale=<tag>`
2. `LC_ALL`
3. `LC_MESSAGES`
4. `LANG`
5. 英文

语言值可以包含 POSIX 后缀，例如 `zh_CN.UTF-8`。不支持的环境语言会回退英文；显式传入不支持的 `--locale` 会报错，不会静默忽略。

繁体中文不会被错误映射为简体中文。在提供 `zh-TW` 语言目录前，`zh-TW`、`zh-HK` 和 `zh-Hant` 均回退英文。

## 回退规则

英文是源语言。翻译缺少某个键时会回退到英文。测试要求每个随项目发布的语言包含完整英文键集，因此回退只是防御措施，不是正常翻译流程。

## 新增语言

1. 将语言标签加入 `SUPPORTED_LOCALES`；
2. 创建 `locales/<tag>.json`，键和占位符必须与 `locales/en.json` 完全一致；
3. 适用时在 `docs/<tag>/` 下添加翻译文档；
4. 运行 `npm run public:check`。

文案插值只替换 `{path}` 这样的命名占位符，不会执行模板、HTML、JavaScript 或 Shell 语法。插值中的控制字符会在输出到终端前转义。

Manifest 字段与 CLI 文案属于两套独立的本地化界面。v1 生产 Manifest 的 `name` 与 `summary` 必须同时提供 `en` 和 `zh-CN`；以后可以直接增加其他合法语言标签，无需修改 Schema。
